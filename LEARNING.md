## Session 2: Optimization Concepts — Practical Testing (June 9, 2026)

### What Anas Learned

**Chunk Size & Overlap:**
- Chunk size determines granularity (smaller = focused, larger = context)
- Overlap = shared text between chunks (prevents boundary loss, like linked list)
- Chunk 500 + overlap 100 = 400 chars new content per chunk
- Tradeoff: more chunks = better precision, fewer chunks = faster search

**Similarity Threshold:**
- **Before:** Return top K results regardless of quality
- **Now:** Filter results by minimum similarity (e.g., keep if similarity ≥ 0.75)
- **Why:** Remove low-confidence matches, improve precision
- Distance ≤ 0.20 = Similarity ≥ 0.80 = 80% confident match

**Query Retrieval Process:**
- Query gets embedded to vector (on-the-fly)
- Compared to all stored chunk vectors (pre-computed during ingestion)
- Distance = how far apart the vectors are (calculated between query vector and each chunk vector)
- Return chunks with smallest distance (closest match)

**Testing & Measurement:**
- Created `test_chunk_sizes.py` to automate chunk size testing
- Modified `ingest.py` to accept CHUNK_SIZE parameter
- Can now test different configurations and measure precision/recall

## Session 1: Core Concepts — Anas's First Deep Dive (May 17, 2026)

### Your Questions & Answers

#### Q1: How do you force remove irrelevancy from results?
**A:** Use similarity threshold. If similarity < 0.75, filter it out. Similar to a game where you pick from [dog, cat, bird, shoe]—shoe is too far (low similarity) so it's rejected.

#### Q2: How is a word/paragraph converted to a number?
**A:** Pre-trained embedding model (Mistral-embed) converts text to 1024 numbers. The model learned patterns from billions of texts to understand relationships:
- "dog" and "cat" → near each other (both animals, pets)
- "dog" and "shoe" → far apart (unrelated)

#### Q3: What is distance in embeddings exactly?
**A:** How far apart two vectors are in space. 
- Distance 0.1 = very similar (0.9 similarity, where similarity = 1 - distance)
- Distance 0.9 = very different (0.1 similarity)

#### Q4: Does the embedding model have a pre-configured mapping like JSON?
**A:** Not exactly. The model is a neural network with learned weights from training on billions of texts. It's not a static mapping—it computes the vector based on learned patterns.

#### Q5: If text spans two paragraphs, how are they compared?
**A:** The entire chunk (whether it spans 1 paragraph or 2) becomes ONE vector. We don't combine distances from two vectors—the chunk IS one vector representing all the text.

#### Q6: How does an LLM decide what text is most appropriate?
**A:** 
1. **Context provides FACTS** (from RAG retrieval)
2. **LLM generates GRAMMAR/STRUCTURE** from learned language patterns
3. LLM generates token-by-token using learned probabilities from training data

Function words like "by", "when", "as" are generated by the LLM, not retrieved from context.

#### Q7: But isn't "best strikers" subjective?
**A:** **Yes, you're right.** This is a real problem in RAG evaluation. Ground truth requires human judgment. Solutions:
- Multiple valid answers per query
- Clearer, more factual queries
- Relevance scoring (not just binary)
- Crowd consensus labeling

## Key Mental Models

### How Embeddings Work
```
Text "dog" (1 word)     → Neural network → [0.5, 0.3, 0.8, ...] (1024 numbers)
Text "The dog barks..." → Neural network → [0.6, 0.2, 0.9, ...] (1024 numbers)

Both are same-sized vectors, regardless of input length.
```

### Distance vs Similarity
```
Distance = how far apart vectors are
Similarity = 1 - distance

Distance 0.2 = Similarity 0.8 (very similar, near each other)
Distance 0.9 = Similarity 0.1 (very different, far apart)
```

### RAG Pipeline
```
1. Query "Messi vs Ronaldo" 
   ↓
2. Embed query → vector
   ↓
3. Compare to all chunk vectors (calculate distance)
   ↓
4. Return chunks closest to query (highest similarity)
   ↓
5. LLM reads chunks + generates answer
```

### Chunking
```
Text: "The dog is loyal. It barks loudly."
Chunks (size=10, overlap=3):
  - "The dog is"
  - "dog is loy"  ← overlap
  - "is loyal. "
  - etc.

Smaller chunks → more precise retrieval
Larger chunks → more context per result
Overlap → boundary issues handled
```

### Deduplication
```
Raw results (top 8):
  - Messi chunk 1
  - Ronaldo chunk 1
  - Messi chunk 2  ← duplicate subject
  
After dedup:
  - Messi chunk 1  ← keep highest similarity
  - Ronaldo chunk 1
```

## Evaluation Metrics

### Precision@K
**"Of top K results, how many are relevant?"**
```
Expected: [Ronaldo, Haaland, Mbappé]
Retrieved: [Messi, Ronaldo, Neymar, Haaland]

Precision@4 = 2 relevant / 4 returned = 50%
"Are my results good?"
```

### Recall@K
**"Of all relevant results that exist, how many did we find?"**
```
Expected: [Ronaldo, Haaland, Mbappé] (3 total)
Retrieved: [Messi, Ronaldo, Neymar, Haaland]

Recall@4 = 2 found / 3 expected = 67%
"Did I find all of them?"
```

### Current System Performance
- **Precision: 30%** → Returning noise (2 good, 2 bad results typical)
- **Recall: 63%** → Finding most relevant results when they exist

## Concept Connections (How it all fits together)

```
TRAINING DATA (billions of texts)
    |
    v
PRE-TRAINED MODEL learns patterns
    |
    v (produces)
EMBEDDINGS (vectors representing meaning)
    |
    v (stored in)
VECTOR STORE (Chroma in your case)
    |
    +---> Used by RETRIEVAL: find similar chunks
    |       |
    |       v
    |     SIMILARITY SCORE (distance-based ranking)
    |       |
    |       v
    |     FILTERED by THRESHOLD (remove low scores)
    |       |
    |       v
    |     DEDUPLICATED (one result per subject)
    |       |
    |       v
    +---> Passed to LLM as CONTEXT
            |
            v
        LLM generates ANSWER
            |
            v
        EVALUATED by METRICS
        (Precision, Recall, etc.)
```

**Key insight:** Everything flows through embeddings. Better embeddings → better retrieval → better context → better answers.
